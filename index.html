What each workload looks like

Each dot is one request: time goes left to right, and each row is one key. Patterns explain why policies win or lose.

How it works

The same steps run for every request, for every policy.

1Request

A workload generator produces the next key.

2Cache lookup

Found? That is a hit. Not found? A miss.

3Eviction

If the cache is full, the policy picks the item to throw out.

4Measure

Observers count hits, misses and time.

Design patterns

Strategy

Every policy implements one interface, so the cache can swap policy at any time.

Factory

Policies and workloads are created by name, e.g. "lru" or "zipf".

Template Method

All workloads share the same steps; only "which key next" changes.

Observer

Metrics, the tracer and this app's data exporter listen to cache events.

Is this really AI?

Yes. A genetic algorithm is a classic AI search method: the program improves its own rule by testing many candidates and keeping the best, the way evolution works. It is not deep learning, and the result is just four numbers you can read and explain.
